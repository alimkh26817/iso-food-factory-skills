Food Factory Process Sheet Filler (ISO 9001:2015 / FSSC 22000)

Purpose: take a completed reference process workbook (e.g. warehousing) and produce the same workbook for another process (production, QC/laboratory, maintenance, purchasing, ...) in a food/beverage factory, keeping the template's structure and design, with content written in Persian unless told otherwise.

Core rules
Never overwrite the original. Work on a copy; deliver the new file under the name the user gives (e.g. فرایند واحد تولید.xlsx). Say that the reference file is untouched.
Never invent factory facts. Anything specific to the plant (process code, line count/capacity, technology, water source/treatment, critical limits, numeric KPI targets, record retention time, release authority, software system name, legal standard numbers, FSSC category) is written as نیازمند تأیید کارخانه, optionally with the topic in front (e.g. حد: نیازمند تأیید کارخانه). Generic roles and generic good practice may be written normally.
Preserve sheet names, sheet order, column order, headers, merged ranges, fonts, fills, borders, logos/images, RTL view, freeze panes, print titles, fit-to-page, code conventions. Change only what the new process requires.
If the user mentions a skill or template file that is missing from the attachments, say so and state which skill was actually used.
Workflow
Inspect the template fully (openpyxl, run with -I): per sheet dimensions, merged ranges, column widths, row heights, every non-empty cell, style fingerprints (font/size/bold/colour/fill/alignment/border), images count and anchors, auto-filter, print area/titles, header/footer, defined names. Render to PDF with soffice --headless --convert-to pdf and pdftoppm, and look at the pages.
Extract the documentation logic: purpose, scope, owner/sponsor, frequency, key records; turtle model (inputs, outputs, suppliers, customers, resources, methods, KPIs, risks/controls); activity table (activity, responsible, input/trigger, output & records, control/acceptance criteria); KPI table; standards-integration matrix.
Detect template defects and fix them in the new file, then report them: leftover text from another process (names, codes), swapped columns versus headers, content from another domain in the matrix, print area cutting rows, stale footer text/auto-filter range. Do not silently copy defects.
Write the new content (see content guide). Extend tables by copying the style of the alternating template rows (cell._style = copy.copy(...)); for a table followed by another block (matrix after KPIs), unmerge/clear the lower block, rewrite it lower and re-merge title rows. Write values only into top-left cells of merged ranges.
Layout fixes: estimate row heights from text length and column width (roughly 1.3 Persian chars per width unit at 10pt, 1.5 at 9pt; height = lines × font × 1.4 + 8; keep the template minimum). Update print area, auto-filter ref, footer text (process/unit name), workbook title property.
Verify: reload and check images still present (openpyxl keeps them), render to PDF and view every page: no clipped text, headers aligned, logos present. Adjust heights and re-render. LibreOffice rendering may differ slightly from Excel; mention that row heights may need small tweaks.
Deliver the file, then a short summary (what was filled, defects fixed, assumptions, which skill/sources were used) and a table of information needed from the factory (item | where used in the workbook).

Scripting tip: keep the build script as one file with content blocks (turtle sheet, activities, KPIs, matrix) as plain lists so the same logic can be reused for another process by replacing only the content; when programmatically replacing blocks, search for unique markers, not generic comments.

Content guide (ISO 9001:2015 mapping)

Always consider and cite where relevant: 4.4 process approach; 6.1 risks and opportunities; 7.1 resources (7.1.3 infrastructure, 7.1.4 environment, 7.1.5 monitoring/measuring and calibration); 7.2/7.3 competence/awareness; 7.5 documented information; 8.1 operational planning and control (incl. change control); 8.4 externally provided products; 8.5 production (8.5.1 controlled conditions, 8.5.2 identification and traceability, 8.5.4 preservation); 8.6 release of products; 8.7 nonconforming outputs; 9.1 monitoring, measurement, analysis; 10.2 nonconformity and corrective action; 10.3 improvement. FSSC 22000 / ISO 22000:2018 where relevant: 7.1.3/7.1.4 infrastructure and work environment; 8.2 PRPs; 8.3 traceability; 8.5 hazard control (OPRP/CCP); 8.7 control of monitoring and measuring; 8.8 verification; 8.9 control of nonconformities (corrections, corrective action, handling potentially unsafe product, withdrawal/recall). ISO/TS 22002-1 clause numbers must be marked for confirmation against the plant's FSSC category and the standard text. Add ISO 14001/45001/ISO 17025 only if in certification/accreditation scope (حسب دامنه گواهی).

Per-sheet content
Identity + turtle sheet: process name; owner (generic role); sponsor; purpose (outcome + control + traceability); scope with start/end points; frequency (keep template wording); key records; inputs/outputs with record names; suppliers/customers (internal and external); resources/equipment (technology items flagged); methods/procedures; 4–8 KPIs referencing the KPI sheet; risks as risk ← control lines plus a فرصت‌ها: line (6.1); clause reference box.
Activities sheet: 10–14 activities in real sequence from trigger to records/improvement; every row has responsible role, input/trigger, output & records, control/acceptance criteria with ISO clause in parentheses; include stop-the-line / release authority where applicable.
KPI sheet: each KPI has definition and formula, target/frequency (هدف: نیازمند تأیید کارخانه), standard reference, evidence and responsible monitor. Keep header-aligned columns. Matrix block lists ISO 9001 clauses above, FSSC/ISO 22000, and legal/regulatory requirements with owner and practical note.
Process-specific hints (food/beverage)
Production: production plan, material usage authorisation (release status, lot, expiry), preparation/weighing, line start-up and clearance, operation, process parameter control (PRP/OPRP/CCP), in-process QC, nonconforming product, scrap and yield, packaging and labelling, hand-over to finished goods warehouse, batch record and traceability. KPIs: plan attainment, yield, scrap rate, nonconforming rate, in-process control compliance, PRP/OPRP/CCP monitoring compliance, batch record completeness, traceability test, downtime/OEE, on-time corrective actions. Bottled-water risks: microbial/physical/chemical contamination, unreleased/expired material, batch/label mix-up, parameter deviation, equipment/calibration failure, record errors.
QC / laboratory: sampling plan, incoming inspection and release/reject (8.4, 8.6), in-process and finished product testing, water physicochemical/microbiological tests, calibration (7.1.5), reagents/media control, OOS and nonconforming handling (8.7, 10.2), retention samples, records and traceability, complaint investigation. KPIs: incoming and finished-product conformity, OOS rate, release lead time, on-time calibration, sampling-plan completion, corrective-action closure, quality complaints.
Warehousing / maintenance / purchasing: reuse the same logic, swapping activities, KPIs and risks accordingly (e.g. supplier approval 8.4, calibration/PM 7.1.3 and 7.1.5).
Final answer format

Short: what the file is, defects fixed, assumptions, which skill/sources were used, then the factory-information table.
